# Báo cáo về buổi Mini Meetup – Tiêu chuẩn API trong phát triển Backend

## 1. Mục tiêu sự kiện

Buổi Mini Meetup được tổ chức vào ngày 22/08/2026 là một sự kiện chia sẻ kiến thức do cộng đồng FCAJ tổ chức. Sự kiện tập trung vào các tiêu chuẩn API trong phát triển Backend, giúp người tham gia hiểu rõ hơn về vai trò của API trong việc xây dựng và phát triển các hệ thống phần mềm hiện đại.

Các mục tiêu chính của sự kiện bao gồm:

- Hiểu được vai trò của API trong việc kết nối và trao đổi dữ liệu giữa các thành phần của hệ thống.
- Tìm hiểu các tiêu chuẩn và nguyên tắc quan trọng trong thiết kế API cho Backend.
- Hiểu được tầm quan trọng của việc xây dựng API dễ sử dụng, dễ bảo trì và có khả năng mở rộng.
- Khuyến khích tinh thần học hỏi liên tục, chia sẻ kiến thức và phát triển chuyên môn trong cộng đồng công nghệ.

## 2. Diễn giả và chủ đề

- **Nguyễn Nhân – Thành viên FCAJ:** Tiêu chuẩn API trong phát triển Backend.

## 3. Các nội dung chính

### 3.1. Tổng quan về API trong phát triển Backend

Nội dung đầu tiên giới thiệu về API (Application Programming Interface – Giao diện lập trình ứng dụng) và vai trò của API trong việc kết nối các ứng dụng cũng như các thành phần phần mềm.

Những kiến thức chính bao gồm:

- Hiểu khái niệm API và vai trò của API trong kiến trúc phần mềm.
- Nhận biết cách API cho phép giao tiếp giữa các ứng dụng và dịch vụ.
- Hiểu tầm quan trọng của việc thiết kế API rõ ràng, nhất quán và dễ sử dụng.
- Nhận biết vai trò của API trong việc tích hợp các thành phần thuộc những hệ thống lớn hơn.

Thông qua nội dung này, tôi hiểu rõ hơn cách API hỗ trợ giao tiếp giữa các ứng dụng Frontend, dịch vụ Backend và những hệ thống phần mềm khác.

### 3.2. Các tiêu chuẩn và nguyên tắc thiết kế API

Nội dung thứ hai tập trung vào những tiêu chuẩn và nguyên tắc quan trọng trong quá trình phát triển API cho Backend, đặc biệt chú trọng đến khả năng sử dụng, bảo trì và mở rộng.

Các khía cạnh chính bao gồm:

- **Tính nhất quán (Consistency):** Sử dụng quy tắc đặt tên endpoint, cấu trúc dữ liệu và định dạng phản hồi thống nhất.
- **Khả năng sử dụng (Usability):** Thiết kế các endpoint rõ ràng để những ứng dụng và dịch vụ khác có thể dễ dàng tích hợp.
- **Khả năng bảo trì (Maintainability):** Tổ chức API một cách hợp lý nhằm đơn giản hóa việc cập nhật, sửa lỗi và phát triển các tính năng mới.
- **Khả năng mở rộng (Scalability):** Thiết kế cấu trúc API có thể đáp ứng sự phát triển của hệ thống trong tương lai.
- **Tính tương thích (Compatibility):** Hạn chế những thay đổi có thể gây ảnh hưởng đến các ứng dụng đang sử dụng API.

Những nguyên tắc này giúp tôi hiểu rằng phát triển API không chỉ đơn thuần là xử lý các yêu cầu gửi đến hệ thống mà còn cần chú trọng đến chất lượng thiết kế và khả năng bảo trì lâu dài.

### 3.3. Vai trò của API trong các hệ thống hiện đại

Nội dung cuối cùng đề cập đến tầm quan trọng của API trong việc kết nối các dịch vụ và hỗ trợ tích hợp giữa những thành phần trong các hệ thống phần mềm hiện đại.

Các vấn đề quan trọng cần lưu ý bao gồm:

- Xác định rõ mục đích của từng endpoint và dữ liệu mà endpoint cần trao đổi.
- Chuẩn hóa quá trình xử lý yêu cầu, phản hồi và thông báo lỗi.
- Ưu tiên xác thực (Authentication), phân quyền (Authorization) và bảo vệ dữ liệu khi cung cấp API.
- Xem xét việc quản lý phiên bản API (API Versioning) khi chỉnh sửa hoặc bổ sung tính năng mới.
- Xây dựng tài liệu API rõ ràng để hỗ trợ quá trình phát triển và tích hợp.

Thông qua nội dung này, tôi nhận thấy API được thiết kế tốt có thể giảm sự phụ thuộc giữa các thành phần, hỗ trợ tích hợp hệ thống và giúp quá trình phát triển trong tương lai trở nên thuận lợi hơn.

## 4. Kiến thức và kỹ năng đạt được

### 4.1. Kiến thức chuyên môn

- **API và phát triển Backend:** Hiểu rõ hơn vai trò của API trong việc kết nối các thành phần của hệ thống phần mềm.
- **Thiết kế API:** Nhận thức được tầm quan trọng của tính nhất quán, khả năng sử dụng và khả năng bảo trì khi thiết kế API cho Backend.
- **Tích hợp hệ thống:** Tìm hiểu thêm cách API hỗ trợ giao tiếp và trao đổi dữ liệu giữa các ứng dụng và dịch vụ.
- **Bảo mật API:** Nhận thức được sự cần thiết của việc xác thực, phân quyền và bảo vệ dữ liệu khi phát triển các giao diện dịch vụ.
- **Khả năng mở rộng:** Hiểu rằng thiết kế API cần đáp ứng được sự phát triển của hệ thống và những yêu cầu thay đổi trong tương lai.

### 4.2. Kỹ năng phát triển cá nhân

- Cải thiện khả năng tìm hiểu và tiếp thu các khái niệm kỹ thuật mới.
- Hiểu được giá trị của việc chia sẻ kiến thức chuyên môn và kinh nghiệm thực tế trong cộng đồng công nghệ.
- Có thêm động lực tìm hiểu về thiết kế, tài liệu và kiểm thử API.
- Nhận thức được tầm quan trọng của việc học hỏi liên tục để theo kịp sự phát triển của các hệ thống phần mềm hiện đại.

## 5. Ứng dụng vào dự án thực tập

Dự án thực tập của tôi có tên **"Thiết kế và triển khai quy trình CI/CD tự động triển khai ứng dụng web trên nền tảng AWS."**

Những kiến thức thu được từ buổi gặp mặt có thể được áp dụng vào dự án theo các cách sau:

- **Phát triển ứng dụng:** Áp dụng các nguyên tắc thiết kế API khi xem xét và phát triển những thành phần Backend của ứng dụng web Spring Boot.
- **Tích hợp hệ thống:** Hiểu cách API hỗ trợ giao tiếp giữa các thành phần khác nhau của ứng dụng và các dịch vụ bên ngoài.
- **Kiểm thử API:** Xem xét việc kiểm thử API như một phần của quá trình xác minh phần mềm, nhằm kiểm tra việc xử lý yêu cầu, định dạng phản hồi và xử lý lỗi.
- **Bảo mật:** Chú ý đến vấn đề xác thực, phân quyền và bảo vệ dữ liệu khi thiết kế các giao diện của ứng dụng.
- **Tài liệu:** Nhận thức được tầm quan trọng của tài liệu API rõ ràng để giúp ứng dụng dễ bảo trì và phát triển hơn.

Những kiến thức này có thể hỗ trợ xây dựng một ứng dụng web có cấu trúc rõ ràng và dễ bảo trì trước khi tích hợp vào quy trình CI/CD tự động trên AWS.

Nhìn chung, buổi Mini Meetup đã cung cấp những kiến thức hữu ích mà tôi có thể liên hệ với dự án thực tập của mình, đặc biệt trong việc xem xét ứng dụng Spring Boot, tìm hiểu chức năng Backend và chuẩn bị ứng dụng cho quá trình kiểm thử, triển khai tự động.
