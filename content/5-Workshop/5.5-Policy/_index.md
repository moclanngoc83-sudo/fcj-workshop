#### **Step 1: Prepare the EC2 Instance**

1. Sign in to the **AWS Management Console**.
2. Open the **Amazon EC2 console**.
3. Choose **Instances** and select the instance that will host the Spring Boot application.
4. Verify that the instance is in the **Running** state.
5. Record the instance ID for later verification.

The EC2 instance must have a suitable IAM instance profile, network access to the required AWS services, and the **CodeDeploy agent** installed and running.

#### **Step 2: Create an IAM Service Role for CodeDeploy**

1. Open the **IAM console**.
2. Select **Roles**, then click **Create role**.
3. Choose **AWS service** as the trusted entity type.
4. Select **CodeDeploy** as the use case.
5. Attach the appropriate CodeDeploy service permissions.
6. Enter the role name:

   `CodeDeployServiceRole`

7. Choose **Create role**.

Use the role created for CodeDeploy when configuring the deployment group.

#### **Step 3: Create a CodeDeploy Application**

1. Open the **AWS CodeDeploy console**.
2. In the navigation pane, choose **Applications**.
3. Click **Create application**.
4. Enter the application name:

   `cicd-aws-demo-app`

5. For **Compute platform**, select **EC2/On-premises**.
6. Click **Create application**.

#### **Step 4: Create a Deployment Group**

1. Open `cicd-aws-demo-app`.
2. Choose **Create deployment group**.
3. Enter the deployment group name:

   `cicd-aws-demo-deployment-group`

4. Under **Service role**, select `CodeDeployServiceRole`.
5. Under **Deployment type**, select the deployment option appropriate for the workshop.
6. Under **Environment configuration**, select **Amazon EC2 instances**.
7. Configure the instance selection criteria using EC2 tags, ensuring the intended application server is selected.
8. Save the deployment group.

{{% notice warning %}}
Verify the EC2 tags and deployment group configuration before deploying. Selecting the wrong instances may deploy the application to unintended servers.
{{% /notice %}}

#### **Step 5: Prepare the Application Deployment Files**

Open the local project directory:

```powershell
cd D:\cicd-aws-demo
```

Check that the project contains the deployment configuration and scripts:

```powershell
dir
dir scripts
```

The project should contain:

- **`appspec.yml`** — defines the deployment files and lifecycle hooks.
- **`scripts/`** — contains the scripts used during deployment.
- **`pom.xml`** — defines the Maven build configuration.

Check that the script paths and filenames in `appspec.yml` match the files in the project. The deployment scripts must also have the appropriate permissions and commands for the target EC2 operating system.

#### **Step 6: Deploy the Application**

Once the application artifact has been generated by **AWS CodeBuild** and made available to CodeDeploy:

1. Open the **AWS CodeDeploy console**.
2. Select the application `cicd-aws-demo-app`.
3. Open the deployment group `cicd-aws-demo-deployment-group`.
4. Choose **Create deployment**.
5. Select the configured revision source and provide the artifact location and revision details required by your deployment configuration.
6. Start the deployment.

If the project is orchestrated by **AWS CodePipeline**, the pipeline can initiate this deployment stage automatically. In that case, use CodePipeline to run the workflow rather than manually creating a separate deployment.

#### **Step 7: Verify the Deployment Status**

1. Open the deployment details in the **CodeDeploy console**.
2. Review the deployment events.
3. Confirm that the deployment status is **Succeeded**.
4. If the deployment fails, identify the lifecycle event that failed and inspect its logs on the EC2 instance.

Common causes include a missing CodeDeploy agent, incorrect IAM permissions, an invalid `appspec.yml`, missing deployment scripts, or an application startup failure.

#### **Step 8: Test the Web Application**

After a successful deployment, test the application using the EC2 instance's public address or the appropriate application endpoint.

For example:

`http://<EC2-Public-IP>:8080`

Replace `<EC2-Public-IP>` with the actual public IP address of the instance. This example assumes that the application listens on port **8080** and that the instance is configured to accept the test traffic.

If the page responds as expected, the application is running on the EC2 instance.

#### **Section Summary**

In this section, you configured **AWS CodeDeploy**, created a deployment group, and deployed the application artifact to **Amazon EC2**.

The next step is to integrate the source, build, and deployment stages into **AWS CodePipeline** so that the application can be deployed automatically when source code changes are detected.
